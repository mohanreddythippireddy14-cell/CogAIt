## Build and Development Commands

```bash
# Start both frontend (Vite) and backend (Convex) in dev mode
npm run dev

# Start only frontend
npm run dev:frontend

# Start only backend (Convex)
npm run dev:backend

# Build for production
npm run build

# Lint and typecheck (chains: tsc convex -> tsc frontend -> convex dev --once -> vite build)
npm run lint
```

### Convex Codegen and Validation
```bash
# Validate schema/functions and regenerate types
npx convex dev --once

# Typecheck backend only
npx tsc -p convex --noEmit

# Typecheck frontend only
npx tsc -p . --noEmit
```

### Tests
No test runner is currently configured in `package.json`. To add tests, install a framework (e.g., Vitest) and add a test script.

If Vitest is added later:
- Run one test file: `npx vitest file.test.ts`
- Run one test by name: `npx vitest file.test.ts -t "test name"`

## Architecture Overview

### Two-Role System
CogAIt is an AI-powered learning platform with two distinct user roles:
- **Students**: Take assignments, answer questions, interact with tiered AI help system
- **Lecturers**: Create assignments, view analytics and student performance

Routes are role-gated in `src/App.tsx`. User roles are stored in `userProfiles` table.

### Frontend Structure (`src/`)
Note: README references `app/` but the actual frontend code is in `src/`.
- React 19 + Vite + TypeScript + Tailwind CSS
- React Router for navigation with role-based routing
- Convex React hooks (`useQuery`, `useMutation`) for data fetching
- `sonner` for toast notifications

### Backend Structure (`convex/`)
- `schema.ts` - Data model with tables: `userProfiles`, `assignments`, `questions`, `attempts`, `aiInteractions`, `sessionLocks`
- `ai.ts` - Gemini integration for tiered AI tutoring (uses `gemini-pro`)
- `calculations/` - Scoring algorithms:
  - `independence.ts` - Independence score calculation
  - `cognitiveScore.ts` - Cognitive assessment
  - `dependencyAlerts.ts` - At-risk student detection
  - `topicAnalytics.ts` - Topic-level performance analysis
- `router.ts` - Custom HTTP routes (keep auth routes in `http.ts` separate)

### Request Flows

**Student Help Request:**
`QuestionView.tsx` → `api.ai.sendChatMessage` (action) → `api.ai.storeInteraction` + `api.attempts.updateHelpStats`

**Final Scoring (on submission):**
`attempts.submitAttempt` → `maybeCalculateFinalScores()` → `internal.calculations/independence.calculateFinalIndependenceScore` + `internal.calculations/cognitiveScore.calculateAndPatchCognitiveScore`

**Integrity Violation:**
`QuestionView.tsx` (visibility/clipboard events) → `api.attempts.recordViolation` → `api.sessionLocks.logViolation` → auto-submit if `tabSwitchCount >= 3`

### AI Tutoring System
The platform implements 4 progressive help levels defined in `convex/constants.ts`:
1. **Audit Mode** (Level 1) - Logic validation only, exposes gaps via questions
2. **Socratic Mode** (Level 2) - Socratic questioning, no direct answers
3. **Instruction Mode** (Level 3) - Structured guidance and method reminders
4. **Deep Assistance** (Level 4) - Step-by-step breakdown

Students must provide 100+ characters of reasoning before requesting AI help. The system tracks `totalHelpRequests`, `helpLevelsUsed`, and calculates `independenceScore`.

### Exam Integrity
`sessionLocks` table tracks:
- Tab switch count
- Copy/paste attempts
- Violation warnings with timestamps

## Convex Patterns Used

### Function Syntax
Always use the new function syntax with validators:
```typescript
export const f = query({
  args: { ... },
  returns: v.null(),  // Always include return validator
  handler: async (ctx, args) => { ... },
});
```

### Public vs Internal Functions
- Use `query`/`mutation`/`action` for public API
- Use `internalQuery`/`internalMutation`/`internalAction` for private functions
- Reference via `api.filename.fn` (public) or `internal.filename.fn` (internal)

### Database Queries
- Use `.withIndex()` instead of `.filter()` for queries
- Indexes must be queried in the order they're defined
- Use `ctx.db.patch()` for updates, `ctx.db.replace()` for full replacement

### Actions with External APIs
Actions cannot access `ctx.db` directly. Use `ctx.runQuery`/`ctx.runMutation` to interact with the database from within actions.
